rtouti (5/24/2023)
Thanks! So the thing is that if the input (x, y) to the noise function is at the "top right" corner, let's say (2, 2), then it's not actually part of the grid square that goes from (1, 1) bottom left to (2, 2) top right. It's actually part of the grid square that goes from (2, 2) bottom left to (3, 3) top right. This is because in the code, the `X` and `Y` (note the uppercase) variables are computed as `const X = Math.floor(x) & 255` and `const Y = Math.floor(y) & 255` respectively, and since it's the `floor` function that we use, `X` and `Y` represent the coordinates of the bottom left corner of the grid square. So when the `topRight` variable is computed, it's value (if we still say that the input (x, y) = (2, 2)) will actually be (xf-1, yf-1) = (0-1, 0-1) = (-1, -1). But then when we do the interpolation, `xf` and `yf` will be 0, so `u` and `v` will also be 0, which means the only value used during the interpolation that actually influences the final result is `dotBottomLeft`. `dotTopRight` could indeed be greater than 1 (or smaller than -1), but it won't contribute much to the final result. I'm not sure I fully answered your question so don't hesitate to ask more :)

Sara (5/25/2023)
Hi! Great article, very good explanation! I have a question. What is the relationship between grid control points and frequency? Can we relate frequency as the inverse of the spacing between control points? Thanks!
rtouti (5/25/2023)
Hi Sara, thanks! I believe they are not really related. I think of the frequency as how close the different "samples" of the noise function are. Let's say you plot the graph for a 1 dimensional noise function, and then do a loop where `x` (the input) goes from 0 to 10, stepping by 1 each iteration (x++). You use `x` to sample (compute the value of) that noise function by calling `Noise1D(x)`. If you use a frequency of 0.5, then you're basically sampling the noise function with input values that are closer to one another. When doing `Noise1D(x * 0.5)` inside the loop, it's basically the same as doing `Noise1D(x)` but inside a loop where `x` goes from 0 to 5 with steps of 0.5 (x+=0.5). So in the end, if you use those sampled values to, let's say, create a terrain, the shape of that terrain will be the same as the shape of the noise function. But if the size of the terrain is always the same, using a lower frequency will basically stretch the "features" of the terrain (bumps and downs of the noise function) over the same terrain area, whereas if you use a larger frequency, you're sampling the noise function over a larger range but also squeezing all of those bumps and downs inside the same terrain area. Don't hesitate to ask again if I didn't correctly answer your question :)

rtouti (9/24/2023)
It's a "bitwise and" operator. It's something that's built-in several programming languages. It's used to manipulate the individual bits of numbers. In this specific case, doing "Math.floor(x) & 255" is roughly equivalent to doing "Math.floor(x) % 256", but it's usually a lot faster and can also deal with negative numbers better. You can look up "bitwise operators" to find out more about it

BAGG (2/26/2025)
I made it in python: 
import random
import math

class Vector2:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def dot(self, other):
        return self.x * other.x + self.y * other.y

def shuffle(array_to_shuffle):
    for e in range(len(array_to_shuffle)-1, 0, -1):
        index = random.randint(0, e-1)
        array_to_shuffle[e], array_to_shuffle[index] = array_to_shuffle[index], array_to_shuffle[e] 

def make_permutation():
    permutation = list(range(256))
    shuffle(permutation)
    permutation.extend(permutation) # Repeat the array
    return permutation

# Generate permutation table
permutation = make_permutation()

def get_constant_vector(v):
    # v is the value from the permutation table
    h = v & 3
    if h == 0:
        return Vector2(1.0, 1.0)
    elif h == 1:
        return Vector2(-1.0, 1.0)
    elif h == 2:
        return Vector2(-1.0, -1.0)
    else:
        return Vector2(1.0, -1.0)

def fade(t):
    return ((6 * t - 15) * t + 10) * t * t * t

def lerp(t, a1, a2):
    return a1 + t * (a2 - a1)

def noise2d(x, y):
    X = math.floor(x) & 255
    Y = math.floor(y) & 255

    xf = x - math.floor(x)
    yf = y - math.floor(y)

    top_right = Vector2(xf - 1.0, yf - 1.0)
    top_left = Vector2(xf, yf - 1.0)
    bottom_right = Vector2(xf - 1.0, yf)
    bottom_left = Vector2(xf, yf)

    # Select a value from the permutation array for each of the 4 corners
    value_top_right = permutation[permutation[X + 1] + Y + 1]
    value_top_left = permutation[permutation[X] + Y + 1]
    value_bottom_right = permutation[permutation[X + 1] + Y]
    value_bottom_left = permutation[permutation[X] + Y]

    dot_top_right = top_right.dot(get_constant_vector(value_top_right))
    dot_top_left = top_left.dot(get_constant_vector(value_top_left))
    dot_bottom_right = bottom_right.dot(get_constant_vector(value_bottom_right))
    dot_bottom_left = bottom_left.dot(get_constant_vector(value_bottom_left))

    u = fade(xf)
    v = fade(yf)

    return lerp(u,
                lerp(v, dot_bottom_left, dot_top_left),
                lerp(v, dot_bottom_right, dot_top_right)
            )

# Example usage
x, y = 5.3, 4.8
result = noise2d(x, y)
print(result)
